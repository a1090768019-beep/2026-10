# دليل بدء التشغيل — Business ERP Desktop

> هذه حزمة بناء Windows x64 من مستودع التطوير. ليست إصدارًا معتمدًا للبيع ولا يجوز استخدامها لتسجيل قيود أو فواتير ضريبية حقيقية قبل استكمال بوابات الإطلاق الموضحة أدناه.

## 1. المتطلبات قبل تسجيل الدخول

يجب أن يكون مسؤول النشر قد جهّز:
- عنوان HTTPS فعليًا لخادم Business ERP API، مع PostgreSQL خاص ونسخة احتياطية مجرّبة.
- موفر OpenID Connect فعليًا وتطبيق Native/Public Client مسجلًا له.
- مستخدمًا داخليًا في النظام وعضوية مستأجر نشطة، ودورًا مناسبًا للشركة.
- إعدادات API متطابقة مع موفر الهوية، خاصة Authority وAudience.

## 2. ضبط ملف الإعداد

بعد فك ضغط الحزمة، افتح `appsettings.json` في مجلد التطبيق باستخدام محرر نصوص، ثم غيّر القيم التالية إلى القيم التي يزوّدك بها مسؤول البيئة:

```json
{
  "ApiBaseUrl": "https://erp-api.example.com",
  "Oidc": {
    "Authority": "https://identity.example.com/",
    "ClientId": "CLIENT_ID_FROM_IDENTITY_PROVIDER",
    "Scope": "openid profile email offline_access business-erp-api",
    "RedirectUri": "http://127.0.0.1:7890/callback/"
  }
}
```

القيم الواردة هنا أمثلة توضيحية فقط؛ لا تستخدم النطاقات أو Client ID الوهمية. لا تضع كلمة مرور أو client secret أو شهادة خاصة في هذا الملف أو في برنامج Windows.

سجّل callback التالي حرفيًا لدى موفر الهوية كتدفق Native/Public Client:

`http://127.0.0.1:7890/callback/`

ينبغي أن يصدر موفر الهوية Access Token صالحًا للجمهور الذي يقبله API. وفي إعدادات API على الخادم يجب أن تتطابق `Authentication:Authority` و`Authentication:Audience` مع موفر الهوية الفعلي. يجب تهيئة المطابقة بين claim `sub` وصف المستخدم الداخلي، مع عضوية مستأجر نشطة. أدخل GUID المستأجر الذي خصّصه مسؤول النظام عند الطلب.

## 3. التشغيل والتحقق

1. شغّل `BusinessERP.Desktop.exe`.
2. اختبر تسجيل الدخول عبر المتصفح، وحدد المستأجر المخصص لك.
3. اختبر الاتصال بخادم الاختبار أولًا، وتأكد من أن الشركة والفترة المالية ودليل الحسابات صحيحة.
4. تحقّق من سجلات API ومؤشرات الصحة في الخادم عند تعذّر الاتصال. لا تعطل TLS ولا تخفف التحقق من الشهادات لمعالجة الخطأ.

## 4. حدود هذه الحزمة

- لا تتضمن API أو PostgreSQL أو إعداد موفر الهوية أو بيانات دخول صالحة.
- القيمة الافتراضية في `appsettings.json` محلية للتطوير؛ يجب استبدالها بعنوان HTTPS قبل تشغيل الحزمة في بيئة العميل.
- لا يوجد مثبت Windows موقّع بشهادة ناشر ولا تحديث تلقائي موقّع.
- لم يثبت تكامل ZATCA/FATOORA أو إصدار الفواتير الإلكترونية القانونية؛ لا تستخدم شاشات مسودات المبيعات الحالية على أنها فوترة ضريبية معتمدة.
- لا يوجد حتى الآن checkout أو تحصيل اشتراكات SaaS أو فرض تلقائي لحدود الخطط.
- نجاح البناء والاختبارات لا يساوي مراجعة أمنية أو محاسبية أو ضريبية مستقلة.

لا توصل الحزمة ببيانات مالية فعلية قبل استيفاء `docs/RELEASE-CHECKLIST.md` بالكامل وقبول المسؤولين للمخاطر المتبقية.
