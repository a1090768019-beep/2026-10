# نشر Business ERP API بواسطة Docker Compose

هذه ملفات تشغيل أولية قابلة للبناء، وليست إثباتًا بأن المنتج اجتاز اعتمادًا تجاريًا أو ضريبيًا. لا تنشر الخدمة للعامة قبل إكمال بوابات `docs/RELEASE-CHECKLIST.md`.

## المتطلبات قبل التشغيل

- Docker Engine مع Docker Compose v2.
- PostgreSQL خاص/مُدار يمكن للخادم الوصول إليه، مع نسخ احتياطي ومراقبة وخطة استعادة مجرّبة. ملف Compose لا ينشئ قاعدة بيانات ولا يعرّضها للإنترنت.
- موفر OpenID Connect فعلي يصدر access tokens للجمهور المحدد، مع مستخدمين محليين وعضويات مستأجرين مهيأة في قاعدة البيانات.
- اسم نطاق ووكيل عكسي موثوق ينهي TLS ويحد معدل الطلبات وحجمها. منفذ API مربوط إلى `127.0.0.1` عمدًا وليس منفذًا عامًا.

## 1. إعداد قاعدة البيانات

راجع `database/README.md` وشغّل ملفات `database/migrations/0001_initial.sql` إلى آخر ترحيل بترتيب الاسم، على قاعدة جديدة أو عبر مسار ترقية مختبر ومعتمد. استخدم دور ترحيلات منفصلًا. لا تعِد تشغيل bootstrap على قاعدة موجودة ولا تتجاوز أول خطأ.

يجب أن يستخدم API دور تشغيل محدود الصلاحيات، لا مالك الجداول ولا `SUPERUSER` ولا `BYPASSRLS`. لا تستخدم اتصال الترحيلات في `ERP_CONNECTION_STRING`. تحقق من صلاحيات RLS ومن إعداد دور التشغيل قبل إدخال بيانات فعلية.

## 2. إعداد الأسرار

مرّر المتغيرات التالية من مدير أسرار أو بيئة محمية على الخادم. لا تحفظ كلمات مرور أو مفاتيح أو شهادات في Git أو في صورة Docker أو سجلات الأوامر.

- `ERP_CONNECTION_STRING`: سلسلة اتصال .NET بـ PostgreSQL باستخدام دور التشغيل محدود الصلاحيات.
- `ERP_OIDC_AUTHORITY`: عنوان Authority لدى موفر الهوية.
- `ERP_OIDC_AUDIENCE`: الجمهور الصحيح لرموز API.
- `ERP_API_PORT` (اختياري): منفذ loopback المحلي؛ افتراضيًا `5080`.
- `ERP_API_IMAGE` (اختياري): اسم ووسم صورة API.

يجب إنشاء المستخدم الداخلي وربط `oidc_subject` بالقيمة الفعلية للـ claim `sub` وإنشاء عضويته النشطة قبل استخدام API. راجع تعليمات تهيئة OIDC في ملف README الرئيسي.

## 3. البناء والتشغيل

من جذر المستودع، وبعد تحميل المتغيرات من مدير الأسرار إلى بيئة العملية:

```bash
docker compose -f deploy/compose.production.yml config --quiet
docker compose -f deploy/compose.production.yml up -d --build
docker compose -f deploy/compose.production.yml ps
```

إذا كنت تستخدم ملف بيئة محميًا خارج المستودع، أضف `--env-file /absolute/path/to/api.env` إلى أوامر Compose، واضبط صلاحيات الملف للقراءة من حساب النشر فقط. لا تضع الملف داخل المستودع.

تحقق محليًا على الخادم:

```bash
curl --fail http://127.0.0.1:${ERP_API_PORT:-5080}/health/live
curl --fail http://127.0.0.1:${ERP_API_PORT:-5080}/health/ready
```

اجعل الوكيل العكسي وحده يصل إلى المنفذ المحلي وفعّل HTTPS عامًّا. مستند OpenAPI لا يُعرض إلا في بيئة Development. قبل أي تحديث: اختبر الترحيلات والنسخة في staging، خذ نسخة احتياطية، واحتفظ بخطة rollback متوافقة مع مخطط قاعدة البيانات.

## تطبيق Windows

ينتج فحص CI حزمة Windows x64 ذاتية الاحتواء من مشروع WPF. الحزمة لا تتضمن API أو PostgreSQL أو موفر الهوية أو إعدادات مؤسسة مهيأة. قبل تسليمها لعميل، اضبط `ApiBaseUrl` إلى عنوان HTTPS الحقيقي و`Oidc:Authority` و`Oidc:ClientId` وفق تطبيق Native/Public Client مسجل لدى موفر الهوية. سجّل callback التالي حرفيًا لدى الموفر:

`http://127.0.0.1:7890/callback/`

لا تضع client secret في برنامج WPF. اختبر الدخول والخروج وانتهاء الرموز وتجديدها فعليًا مع موفر الهوية المستهدف.

## ما لا يوفره هذا الملف

لا ينشئ موارد سحابية أو DNS أو شهادات TLS أو قاعدة بيانات مُدارة أو إعداد OIDC، ولا ينفذ النسخ الاحتياطي أو الاستعادة تلقائيًا، ولا يضيف تكامل ZATCA أو مدفوعات الاشتراك. هذه مهام تشغيل واعتماد منفصلة ويجب إثباتها وفق قائمة قبول الإصدار.
