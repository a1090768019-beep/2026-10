# خارطة تنفيذ مرحلية

تعكس الحالة أدناه ما هو موجود فعلًا في المستودع ونتائج CI، لا التقدير النظري. نجاح البناء واختبارات الدخان لا يعني الجاهزية للاستخدام المالي الإنتاجي.

| المرحلة | النتيجة المطلوبة | الحالة الفعلية |
|---|---|---|
| 0 — تحليل وتصميم | المتطلبات، المعمارية، نموذج التهديدات، نموذج البيانات وقرارات موثقة | مسودات موجودة؛ ما زالت تحتاج مراجعة هندسية ومحاسبية وقانونية |
| 1 — تأسيس المشروع | مشاريع .NET، تطبيق WPF، API، مخطط PostgreSQL وCI | الهيكل موجود؛ CI يبني API وWPF على Linux/Windows بنجاح |
| 2 — النواة المحاسبية | دليل الحسابات والفترات والقيود والترحيل والعكس والأستاذ وميزان المراجعة | مسار API أولي موجود؛ 8 اختبارات مجال ناجحة؛ CI يطبق مخطط PostgreSQL ويختبر RLS وقواعد القيد بدور تشغيل محدود |
| 3 — العمليات | المبيعات والمشتريات والصناديق والبنوك والمخزون وربطها بالمحاسبة | العملاء والمسودات محفوظة مع RLS وأقفال ترقيم وقيود إجماليات؛ تصنيف VAT ومبالغها تحفظ على المسودة داخليًا، ويمكن ترحيل الأثر بقيد GL متوازن مربوط بالمصدر ومحصّن من التكرار/التعديل. لا توجد فاتورة قانونية/ ZATCA أو تحصيل ومردودات. |
| 4 — SaaS | الخطط والاشتراكات والفوترة والدفع والتجديد والحصص ولوحة المشغل | المخطط موجود؛ واجهات قراءة للخطط وحالة الاشتراك فقط. لا يوجد checkout أو دفع أو فرض حصص أو تسجيل ذاتي |
| 5 — الامتثال السعودي | VAT وفاتورة الإلكترونية والتوقيع/التجزئة وQR وتكامل FATOORA واختبارات sandbox | لم ينفذ تكامل ZATCA؛ المعاينة الضريبية داخلية فقط، ولا يجوز وصف المنتج بأنه متوافق أو معتمد |
| 6 — وحدات متقدمة | الأصول والرواتب والمشاريع والتصنيع وتقارير متقدمة | لم تبدأ |
| 7 — إطلاق تجاري | أمن وأداء واستعادة وتحديثات وتوزيع Windows وتشغيل ودعم إنتاجي | غير جاهز؛ لم تُنجز مراجعة محاسبية أو اختبار اختراق أو استعادة إنتاجية |

## ما تم التحقق منه آليًا

- بناء مشروع API على .NET 10.
- بناء تطبيق WPF على عامل Windows.
- اجتياز 8 اختبارات للنواة المحاسبية.
- اجتياز فحوص العقود المصدرية بواسطة Node.js.
- تطبيق مخطط bootstrap على PostgreSQL 17 من قاعدة فارغة.
- استخدام دور PostgreSQL غير مالك وغير superuser لاختبار RLS.
- إثبات عزل بيانات مستأجرين في اختبار الدخان، ورفض ترحيل قيد غير متوازن، ورفض سطر فيه مدين ودائن معًا، ومنع تعديل القيد المرحّل.
- فحوص concurrency بالمصدر لأقفال إنشاء القيود والعكس وتداخل السنوات المالية؛ ما زال اختبار ضغط API متعدد الطلبات مطلوبًا.

## الأولويات العملية التالية

1. إنشاء اختبارات API تكاملية عبر ASP.NET TestServer مع PostgreSQL وموفر هوية اختباري، والتحقق من أن طلبات عميل لا يمكنها قراءة بيانات مستأجر آخر.
2. اختيار موفر OIDC وتوصيل تسجيل الدخول المكتبي وإدارة الجلسات/الرموز والاسترداد قبل فتح واجهة العمليات.
3. بناء إجراءات مشغل المنصة لتهيئة الخطط وتخصيص الاشتراكات ودعوات المستخدمين والتدقيق، ثم اختيار بوابة الدفع وإضافة التحقق من webhooks وتسوية الأحداث المتكررة.
4. إكمال دورة المبيعات بVAT موثقة وفاتورة نهائية/مرحلة وترحيل ذري إلى الذمم والإيراد والضريبة، ثم الإشعارات الدائنة والتحصيل.
5. مراجعة متطلبات ZATCA/FATOORA وPDPL وموقع البيانات والبنية السحابية مع الجهات المختصة قبل توصيل بيانات حقيقية.
6. تجهيز سياسة ترحيلات تزايدية، وصلاحيات إنتاج، ونسخ احتياطي واستعادة، ومراجعة أمنية واختبار اختراق قبل إطلاق تجاري.

## قيود الإصدار الحالي

- واجهة WPF بها OIDC قابل للتهيئة وRibbon قابل للطي وتبويبات مساحة عمل وبحث محمّل واختصارات، وشاشة مبيعات RTL متصلة بإنشاء العملاء والمسودات وVAT وGL. بقية شاشات المحاسبة/التقارير/المشتريات/المخزون غير متصلة بعد، وموفر الهوية لم يُختبر حيًا.
- مخطط قاعدة البيانات bootstrap فقط. فحوص PostgreSQL في CI تختبر إنشاء القاعدة وقواعد مختارة، وليست بديلًا عن ترحيلات إنتاج تزايدية أو اختبار تشغيل طويل.
- واجهات الاشتراك تعرض بيانات الخطة المسجلة فقط. لا تفرض الحصص ولا تثبت تحصيل الأموال.
- لا توجد فاتورة ZATCA، ولا إرسال إلى منصة فاتورة، ولا اعتماد رسمي.
- يجب أن تتم تهيئة أول مستأجر وخطته وعضوياته عبر مشغل موثوق؛ لا يوجد self-service onboarding بعد.
- زر الطباعة/Excel/PDF غير مفعّل، ولا يوجد server-side pagination أو تحديث آمن للتطبيق أو تبويبات متعددة للمستندات. البحث الحالي يصفّي العملاء والمسودات المحمّلة محليًا (مع حد 500 مسودة)، ولا يغني عن بحث خادمي عند نمو البيانات.
