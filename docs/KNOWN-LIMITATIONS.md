# القيود المعروفة

## قيود تمنع البيع
- تطبيق WPF يحتوي على تدفق OIDC قابل للتهيئة وواجهة عملاء/مسودات مبيعات متصلة بالـ API، لكن موفر الهوية غير مهيأ/غير مختبر حيًا؛ بقية شاشات المحاسبة/المشتريات/المخزون ما زالت غير مكتملة.
- المبيعات عملاء ومسودات داخلية فقط؛ لا VAT ولا فاتورة ضريبية/مبسطة نهائية ولا خصومات أو إشعارات أو تحصيل أو ترحيل GL.
- لا تكامل ZATCA/FATOORA مثبت ولا XML/توقيع/تجزئة/QR ولا قبول sandbox.
- الاشتراكات للقراءة؛ لا onboarding ذاتي أو فرض حصص أو checkout أو webhooks أو تجديد أو لوحة مشغل.
- لا مشتريات/موردين/مخزون أو تقييم تكلفة، ولا قبض وصرف أو تسوية بنك.
- لا عملات متعددة أو أسعار صرف؛ القيود تستخدم عملة الشركة الأساسية.
- التقارير المتاحة الأستاذ العام وميزان المراجعة؛ ليست قوائم مالية معتمدة مكتملة.
- لا دليل إنتاجي على نشر/مراقبة/backup وrestore أو توقيع وتحديث تطبيق Windows.
- لا مراجعة محاسبية/ضريبية مستقلة أو اختبار اختراق.

## قيود فنية
- 0001_initial.sql هو bootstrap؛ 0002_sales_invoice_drafts.sql ترحيل إضافي لشريحة المسودات فقط.
- يلزم ضبط Oidc:Authority/ClientId/Scope وتسجيل callback لدى موفر هوية، وضبط Authentication:Authority/Audience على API وتوفير مستخدم/عضوية تطابق claim sub. تدفق end-session لدى الموفر غير منفذ؛ الخروج الحالي محلي.
- فحص البريد في API هو تحقق شكلي وليس إثبات ملكية.
- دقة أربع منازل في المسودات مبدئية، وليست سياسة معتمدة للضرائب أو كل العملات.
- نجاح CI لا يثبت اعتماد قانوني أو أداء إنتاجيًا أو جاهزية بيع.

**التصنيف: غير جاهز للبيع.** استخدمه للتطوير والاختبار حتى استيفاء RELEASE-CHECKLIST.
