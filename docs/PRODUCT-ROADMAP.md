# خارطة طريق المنتج — Business ERP SaaS

## التصنيف الحالي: غير جاهز للبيع
المستودع يضم نواة محاسبية أولية ومسودات مبيعات ومشتريات داخلية، وفرضًا أساسيًا لحالة الاشتراك وحصتي الشركات والقيود الشهرية. تم تنفيذ موردين ومسودات فواتير شراء وحساب VAT داخلي وتقرير تفاصيل وترحيل GL مزدوج مربوط بالمصدر مرة واحدة؛ لا توجد دورة مشتريات كاملة بالمدفوعات والمخزون، ولا فاتورة ضريبية نهائية أو اعتماد ZATCA أو دفع SaaS أو تشغيل تجاري مثبت.

| المجال | الحالة الحالية | معيار القبول |
|---|---|---|
| التأسيس | Modular monolith: WPF, ASP.NET Core, PostgreSQL وCI | بناء كل المشاريع واختبار DB/API موثق |
| الهوية والعزل | JWT/عضوية/RLS في الخادم، وعميل OIDC WPF بمتصفح النظام وcallback loopback | اختيار وتهيئة موفر فعلي واختبار دخول حي؛ مصفوفة صلاحيات واختبارات IDOR وعزل أوسع |
| المحاسبة | قيود، ترحيل/عكس، الأستاذ العام وميزان مراجعة أولي | تطابق التقارير مع القيود المرحلة وسياسات الإقفال ومراجعة محاسب |
| المبيعات | العملاء ومسودات المبيعات؛ حساب VAT يمكن حفظه الآن داخل المسودة مع RLS وقيود إجماليات DB. أضيف ترحيل GL داخلي ذري مربوط بالمصدر؛ ما يزال إصدار فاتورة نهائية وZATCA غير منفذين. | فاتورة نهائية حسب نوع التوريد، قيد GL ذري للذمم/الإيراد/VAT، إشعارات دائنة، تحصيل وأعمار ديون |
| المشتريات والمخزون | موردون ومسودات فواتير شراء داخلية؛ حساب VAT محفوظ لكل بند وتقرير مفصل؛ ترحيل GL مزدوج مع ربط المصدر ومنع إعادة الترحيل، ويمكن ترك VAT ضمن التكلفة أو اختيار حساب أصل بناءً على قرار المستخدم | دورة شراء متكاملة تشمل مدفوعات الموردين، إشعارات دائنة، مطابقة مستندات المصدر، الأصناف والمخزون وتكلفة المخزون، مراجعة محاسبية وإثبات تحقق VAT input recovery خارج النظام |
| SaaS التجاري | قراءة خطة/اشتراك؛ بوابة وصول للاشتراك الساري، حدود الشركات والقيود الشهرية والمستخدمين النشطين مفروضة، وواجهات OWNER/ADMIN لإسناد العضويات وإدارة الأدوار والحالة للمستخدمين المجهزين مسبقًا | onboarding ذاتي، دعوات موثقة، إنشاء مستخدم لدى موفر الهوية، checkout، مزود دفع وwebhooks وتجديد ولوحة مشغل |
| ZATCA | لا تكامل مثبت | مواصفات رسمية منطبقة، sandbox واختبارات/إجراءات إنتاج مطلوبة |
| Windows | WPF بهوية قابلة للتهيئة وRibbon Office-like؛ واجهة مبيعات ومساحة مشتريات RTL متصلة بـ API، ومسودة المورد وVAT الداخلي وترحيل GL وتقرير مشتريات؛ تبويب فهرس قوالب REPX | اختبار موفر OIDC حي، تشغيل/معاينة قوالب REPX بمحرك مرخص وربط بياناتها، استكمال شاشات المحاسبة والمخزون، اختبار عملي للتقارير والطباعة/التصدير على جهاز نظيف وتوزيع آمن |
| التشغيل | لا توجد أدلة تشغيل إنتاجي | staging، TLS، secrets، مراقبة، backup/restore وrollback |
| الإطلاق | غير جاهز | استيفاء RELEASE-CHECKLIST بالكامل |

## تسلسل التنفيذ
1. تثبيت ترحيلات قاعدة البيانات بدور محدود وفحص عزل RLS.
2. إثبات عمل customer/draft API على PostgreSQL، وإصلاح أخطاء CI لا تخفيف الاختبارات.
3. اعتماد سياسة VAT والتقريب من مصادرها ومراجع محاسبي قبل إنشاء فاتورة نهائية.
4. بناء خدمة إصدار/ترحيل واحدة تكتب المستند والقيد وسجل التدقيق ومفتاح المصدر في معاملة واحدة.
5. إضافة الإشعارات الدائنة والمدفوعات ثم تقارير الذمم.
6. تشغيل تدفق WPF مع موفر OIDC اختير فعليًا، ثم توسيع MVVM إلى الحسابات والتقارير والصلاحيات، وإكمال البحث server-side والتصفية والصفحات والتصدير والطباعة.
7. استكمال المشتريات بالمدفوعات والإشعارات والمطابقة، ثم بناء المخزون وتكلفته وربطه بالقيود؛ بعدها SaaS payments.
8. اختبار ZATCA حسب انطباق المتطلبات، ثم تجهيز الأمن والنشر والتوزيع.

لا تُعتبر الميزة مكتملة من وجود ملف أو شاشة؛ يلزم اختبار يثبت المسار من HTTP إلى PostgreSQL والأثر المحاسبي حيث ينطبق.
